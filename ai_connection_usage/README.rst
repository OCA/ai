This module records every call made through an AI Connection and lets
administrators control what those calls cost.

- One usage row per call: connection, company, user, purpose and related
  record, AI model, prompt and completion tokens, cost, duration and
  error. Prompts and answers are **not** stored unless a connection asks
  for it.
- Prices per connection (per million input and output tokens, in a
  currency), so each row carries its computed cost.
- An optional company on the connection, to know whose spend a call is.
- Optional monthly spending caps, per company and per connection. Once a
  cap is reached the next call is refused with a clear message, before
  anything is sent to the provider.

Usage rows are written in a transaction of their own, so the row of a
failed call is kept even when the caller rolls back.

Configuration
=============

In Settings > Technical > AI > AI Connection, open a connection:

- set its Company, or leave it empty to count each call against the
  current company of the user;
- in the Usage tab, set the price currency, the input and output prices
  per million tokens, the optional monthly cap of the connection, and
  whether prompts and answers are kept in the log.

The monthly cap of a company is set on the company form (AI Monthly
Spending Cap, in the company currency). Zero means no cap.

Only administrators (Settings) can see and change prices, caps and the
stored prompts and answers.

The day of each call, and so the month the caps count, is taken in the
timezone of the system parameter ``ai_connection_usage.timezone`` (for
example ``America/Argentina/Buenos_Aires``); UTC when it is not set.

Usage
=====

Nothing changes for the code calling ``ai.connection._run``: each call
is logged automatically. Settings > Technical > AI > AI Usage lists the
calls, filtered on the current month, with totals and a pivot by
connection and month. Administrators see every call; other users only
see their own.

A caller can name what the call is for with the ``ai_usage_purpose``
context key; the ``record`` given to ``_run`` is kept as the related
record:

.. code:: python

   connection.with_context(ai_usage_purpose="product_description")._run(
       prompt=prompt, record=product
   )

Integrators that also pay for AI calls made outside of ``ai.connection``
can override
``ai.connection._usage_external_month_spend(company, date)`` to return
that spend (in the company currency), so the company cap counts it too.

Known issues / Roadmap
======================

- The caps are soft limits. They are checked before each call, so the
  call that crosses a cap is still made, and calls running at the same
  time can all pass the check: the overshoot is at most one call per
  concurrent request. Serializing the calls of a company (a lock held
  during the provider call, up to its timeout) would make every AI
  feature of the company wait on the slowest one, and was left out on
  purpose.
- A failed call is logged with cost 0. Providers usually do not bill a
  request that fails, but one that times out after generating may be
  billed.
- Costs come from the token counts reported by the provider and the
  prices configured on the connection; they are an estimate, not an
  invoice.
